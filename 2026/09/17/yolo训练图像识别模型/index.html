此为学校机器人实验室入组考核材料

原始考核材料仓库：https://github.com/wei-a11y/yolov5_master.git

——————————————————

训练显卡：GTX 1650

系统：Ubuntu 22.04.5 LTS

电脑品牌：拯救者

————————————

以下为完成考核的过程，以及遇到的一些问题及解决方案

1系统安装

根据教程 BV1Cc41127B9 安装Ubuntu 22.04.5 LTS

此版本为稳定版本

教程评论区的大部分问题都是没有下载22.04版本,而是下载了更新的版本导致的

U盘引导

跟着B站的教程视频安装了U盘引导

选择cmdpe作为备用救急系统（早些年的付费资源，现在官网已经停止维护，使用的是个人网盘的版本）

2模型训练准备

访问github

考核点1：Ubuntu中可以使用watt tookit，解压后右键Steam++.sh文件选择作为程序运行即可

软件安装

  • git

  • anconda

  • vs code

[Ubuntu装vscode真爽，输输指令就自己装好了，运行只需要命令行输入code就能启动]

3模型训练

跟着教程完整走过一遍后，发现存在一些问题

  • 识别类型名称为remote

  • 自己的数据集和官方的coco数据集混在一起

  • 模型预测的概率偏低，静态图片仅为0.52

4模型优化

考核点2：yolov5训练流程.ipynb中4.2的训练命令没有把前面下载的预训练yolov5s.yaml加入运算

考核点3：conda和pip混用，容易装错labelimg

针对3中存在的问题进行了一些分析和整改

识别类型名称

remote为coco数据集的类别，并非命名错误，本质上还是训练的时候把coco数据集一起训练进去，且我自己的数据权重极低，导致不可能被识别出来，才让我误判了问题类型

数据集混合

在第570行 –data的默认参数是coco数据集，如果不写这个参数就会默认使用coco数据集，说明第一次的训练并没有加入我自己的数据，而是我的识别物体与coco数据集的其他物体形态相近导致出现了标注框，让我再次误判了问题类型

想要纠正这个错误，只需要在训练命令中加入–data参数即可纠正这个全篇最大的问题

预测效果不佳

第一轮训练的图片样本数量较少，不足10个，导致拟合效果不佳，后期增加训练图片数量到46（20%作为验证集）
静态图片识别率到了0.79，摄像头识别率到了0.33

5发现问题

发现静态图片和摄像头识别率相差过大，查找资料后认定是数据泄露和过拟合，本质上还是训练样本数量不足

另外，在前期的训练图片中，场景和光照都十分相似，这也是导致训练效果不佳的一个重要原因

6再次优化

查了一些资料，发现前期对数据集的划分有一些问题

AI说更好的情况是，数据集应该有80%左右是真实背景，20%是纯色背景

而且还需要加入一些负样本（图片中不存在目标物体）

但是我实际执行中发现，如果不在labelImg中拉框，则这个图片会被transform.py文件自动跳过

考虑到图像识别对背景的状态较为敏感，因此想快速提高摄像头识别率的方法也简单，就是截图一些摄像头拍摄的图片，把这些图片放到训练集中。

虽然说这方法为一开始认为有点作弊（数据泄露抄答案），但同时我了解到在真实生产应用中也会常常把大量真实工作场景作为背景加入到模型的训练中。

最终训练命令参数

python train.py
–data data/my_dataset.yaml
–weights yolov5s.pt
–img 640
–batch 8
–nbs 8
–noamp
–epochs 200
–name my_zhijiadao_v6

参数解释

  • 模型训练图片较少，仅为50张，根据图片数量设定nbs参数为8

  • 受显卡GTX 1650的限制（4GB），batch参数降低到8

  • 关闭 AMP 自动混合精度，实测如果开启会溢出产生NaN导致训练无效

最终结果

静态图片识别准确率提升到0.88

摄像头识别准确率提升到0.84

还是那句话，识别准确率与背景关系大，晚上宿舍关灯后物体更加突出

识别准确率就提高了更多

个人收获

  • 学会Ubuntu的安装和基础使用
  • 更新自己的U盘引导工具
  • 独立完成了图像模型训练的全流程，明白数据标注、模型调优的原理
  • 对conda有了更深的理解
